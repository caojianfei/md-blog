# 首页 Hero 留白卡通填充设计方案

## Summary

目标是在宽屏模式下，为首页左侧 `hero-panel` 中标题与描述下方的大块留白补充一组有趣、克制、符合当前“极简技术感”风格的卡通形象与动作内容，让页面更完整、更有记忆点，同时不破坏当前首页的信息层级与内容优先原则。

推荐方向为“终端实验室值班员”方案：在 `hero-panel` 下半区加入 2 到 3 个轻量卡通角色，围绕“写作、构建、调试、发布”做循环动作，视觉上保持线性插画、低饱和点缀色、带少量终端/代码元素，与右侧终端面板形成呼应。

## Current State Analysis

- 当前首页模板位于 `web/templates/pages/home.html`，Hero 区结构为左侧 `hero-panel`、右侧 `terminal-panel`。
- `hero-panel` 目前仅包含 `eyebrow`、`h1`、`p`，没有下半区内容。
- `web/assets/style.css` 中 `.hero-grid` 在宽屏使用双列布局，`grid-template-columns: minmax(0, 1.5fr) minmax(280px, 0.9fr)`，并设置 `align-items: stretch`。
- 由于右侧 `terminal-panel` 更高，左侧 `hero-panel` 会被拉伸到同等高度；内部内容不足时，就形成用户截图中的留白。
- 在 `1080px` 以下，`.hero-grid` 会切为单列，因此该问题主要出现在宽屏桌面布局。
- 当前前台整体风格已确定为深色科技感、极简、内容优先、终端/代码语义化视觉，因此新增元素不能走高饱和彩色插画路线，也不宜做过于“萌系”或儿童化表达。

## Assumptions & Decisions

- 设计目标是“填充留白并增强品牌识别”，不是新增功能模块，因此新增内容应偏装饰性叙事而不是信息卡片。
- 填充内容仅在宽屏/大屏起主要作用；中小屏应降级为更简洁的静态编排，避免挤压正文首屏。
- 卡通形象建议使用纯前端可控的实现方式，优先 SVG/HTML/CSS 组合，而不是依赖外部位图资源。
- 动效保持轻量，优先使用 `transform`、`opacity`、`stroke-dashoffset` 一类低成本动画，并支持 `prefers-reduced-motion` 降级。
- 视觉语义需与右侧终端联动，形成“左侧角色在工作，右侧终端正在响应”的叙事关系。

## Proposed Changes

### 1. 推荐视觉概念：终端实验室值班员

在 `hero-panel` 内标题与描述下方新增一个视觉舞台区，命名可暂定为 `hero-scene`。该区域表现为一个“微型终端实验台”：

- 一个主角色：戴耳机的极简工程师，坐姿或半站姿，正在敲键盘。
- 两个辅助角色：一个搬运小方块文件夹、一个举着扳手或光标旗标，表现“构建”和“调试”。
- 场景道具：小尺寸显示器、浮动命令气泡、像素星点、进度线、文件块、箭头轨迹。
- 动作建议：
  - 主角色手部轻微上下，模拟敲击键盘。
  - 辅助角色 A 做“递送文档块”动作，沿短路径往返。
  - 辅助角色 B 做“检查/挥旗/点亮状态灯”动作。
  - 背景中 1 到 2 条扫描线或数据粒子缓慢移动。

该方案优点：

- 与当前终端 UI 语言最一致。
- 叙事明确，容易做得有趣但不幼稚。
- 可以拆成多个独立 SVG 元素，后续易维护、易微调。

### 2. 视觉层级与版式安排

建议把 `hero-panel` 重构为“上文案 + 下场景”的两段式：

- 上半区继续保留 `eyebrow`、主标题、描述文案，维持现有阅读优先级。
- 下半区新增 `hero-scene`，占据剩余可用高度，建议最小高度 220 到 280px。
- 下半区内部采用三层结构：
  - 背景层：网格、淡化圆弧轨迹、噪点、扫描线。
  - 中景层：角色本体与实验台。
  - 前景层：命令标签、小图标、状态灯、移动文件块。
- 为避免“空白被硬塞满”，保留 20% 到 30% 呼吸空间，不把所有区域铺满。

### 3. 视觉语言细节

为贴合当前站点风格，建议遵守以下表达：

- 角色造型：几何化、圆角矩形+线段组合，避免写实插画。
- 线条风格：1.5px 到 2px 为主，搭配少量填充块。
- 主色沿用现有主题变量，以 `var(--primary)` 为高亮；辅助色只增加 1 到 2 个状态色，如薄荷绿、暖黄。
- 面板底色仍用当前 `surface` 体系，角色本身对比略高于背景，但低于主标题。
- 命令气泡文案可使用短 token，如 `build`, `draft`, `ship`, `sync`, `md`, `rss`，强化博客工程感。

### 4. 动效策略

推荐做“低频、错峰、可降级”的轻动画：

- 主角色键盘动作：2.4s 到 3.2s 的微循环。
- 文件块漂移：4s 到 6s 的往返位移。
- 状态灯闪烁：间隔 1.8s 到 2.2s，亮度变化轻微。
- 数据线扫描：6s 到 8s 的长周期平移。
- 悬浮标签：轻微上下浮动 6px 以内。

约束：

- 不使用大幅旋转、缩放弹跳、强烈视差。
- 不让动画抢过标题；视觉注意力仍应先落在文案，再落到场景。
- 在 `prefers-reduced-motion: reduce` 下禁用位移动画，仅保留静态排布。

### 5. 响应式策略

建议按断点分级处理：

- `> 1280px`：完整展示 2 到 3 个角色 + 全部小道具 + 轻动效。
- `1080px - 1280px`：保留主角色和 1 个辅助角色，减少背景装饰密度。
- `<= 1080px`：因为 `hero-grid` 已转单列，`hero-scene` 改为更矮的静态插图区，或者仅保留主角色与两三个命令标签。
- `<= 820px`：进一步压缩为单角色横向小场景，避免首屏过长。

### 6. 具体文件修改建议

#### `web/templates/pages/home.html`

建议在现有 `hero-panel` 中，紧接描述文案后加入一个新容器，例如：

- `hero-scene`
- `hero-scene__stage`
- `hero-scene__character`
- `hero-scene__props`
- `hero-scene__bubble`

实现方式可选：

- 方案 A：直接内联 SVG 到模板中。
  - 优点：结构集中、控制精细、无需新增资源引用。
  - 缺点：模板体积变大。
- 方案 B：使用 HTML 结构 + 少量内联 SVG 图标组合。
  - 优点：更适合用 CSS 做局部动画。
  - 缺点：结构节点会略多。

本项目推荐方案 B：角色躯干和场景主形体用 HTML 结构搭建，复杂图形如命令箭头、小图标用 SVG 补充。

#### `web/assets/style.css`

需要新增以下样式组：

- `hero-panel` 改为纵向布局，使下半区自然吃掉剩余高度。
- `hero-scene` 负责最小高度、边框、内阴影、渐变和背景网格。
- 角色、道具、浮动标签的定位和层级。
- 对应的 `@keyframes` 动画。
- `prefers-reduced-motion` 降级规则。
- 宽屏到中屏的逐级删减样式。

同时建议对 `hero-panel` 做两点小调整：

- 让标题区与场景区之间增加 16 到 24px 间距。
- 让场景区内部形成一个“内嵌画布”边界，而不是直接顶到卡片四周。

### 7. 三个备选创意方向

如果你觉得“终端实验室值班员”还不够有趣，可以在执行前从以下方向中切换：

#### 备选 A：像素邮差小队

- 角色设定：几个像素风小人搬运 Markdown 文稿、标签卡片、归档箱。
- 动作语义：投递、分类、盖章、归档。
- 风格特点：更轻松、更生活化，但技术感略弱于推荐方案。

#### 备选 B：博客维修站

- 角色设定：一个小机器人修理标题下方的数据管线，旁边有机械臂递工具。
- 动作语义：焊接、扫描、点亮、校准。
- 风格特点：更偏未来感，适合强化“技术站点”身份。

#### 备选 C：深夜写作值班室

- 角色设定：一个写作者、一个悬浮光标精灵、一个递咖啡的小助手。
- 动作语义：打字、闪烁、递杯、贴便签。
- 风格特点：氛围感最好，偏内容创作，不如推荐方案那样直接呼应终端。

综合考虑当前首页已有右侧终端，推荐继续采用“终端实验室值班员”。

## Verification Steps

设计确认后，实施阶段应按以下标准验收：

- 宽屏首页首屏中，左侧留白被有效填充，但标题仍是第一视觉焦点。
- 新增卡通元素与右侧终端面板风格统一，不出现强烈风格割裂。
- `1080px` 以下单列布局中，场景不会导致首屏明显过长或信息拥挤。
- 深色与浅色主题下，角色与背景对比清晰，边框和状态色可见。
- 开启动效时页面保持克制，不造成明显干扰；关闭动态偏好时可静态呈现。
- Lighthouse 或手动体验层面无明显性能和可访问性回退。

## Recommended Execution Order

1. 在 `home.html` 中补充 `hero-scene` 结构骨架。
2. 在 `style.css` 中完成静态场景布局和响应式规则。
3. 加入轻量动效与 `prefers-reduced-motion` 降级。
4. 在宽屏、平板、手机三档下检查视觉密度并删减装饰元素。
5. 根据实际观感微调角色数量、动作振幅和装饰密度。
