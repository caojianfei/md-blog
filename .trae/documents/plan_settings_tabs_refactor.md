# 管理后台设置页 Tab 分组重构方案

## Summary

* 目标：将当前后台 `Settings` 页面从“所有配置堆叠在一个长页面”重构为“顶部 Tab 分组切换”的结构，降低视觉噪音，提升定位效率与操作清晰度。

* 范围：仅重构 `web/admin/src/views/Settings.vue` 的前端组织方式与交互呈现，不改动现有后端设置接口、数据结构与保存逻辑。

* 核心策略：保持单路由 `/settings` 不变，在页面内部引入 Tab 状态，把现有分区按语义分组，切换时只展示当前组内容。

## Current State Analysis

### 1. 当前页面是单页长表单

* 当前文件为 `web/admin/src/views/Settings.vue`。

* 页面已包含以下配置区块，按顺序全部铺陈在同一张卡片里：

  * 基本信息

  * 站点运行

  * 存储配置

  * SEO 设置

  * 首页展示

  * 站点展示

  * SEO 高级

  * 关于页内容

  * 安全设置

* 页面顶部只有一个“保存设置”按钮，而安全设置区单独有“保存账号”按钮。

### 2. 当前问题集中在信息组织而非能力缺失

* 字段数量已经较多，且混合了多种不同性质的设置：

  * 站点基础资料

  * 运行配置

  * 存储驱动配置

  * SEO 配置

  * 首页与关于页内容

  * 管理员账号安全

* 用户在同一视窗内会同时看到大量无关字段，容易产生“混乱感”。

* 其中存储配置还带有本地 / S3 的条件渲染，进一步拉长页面高度。

### 3. 仓库中没有现成 Tabs 组件

* 在 `web/admin/src` 中未发现现成的 `Tabs` / `activeTab` 相关实现。

* 后台基础样式主要依赖 Tailwind，适合直接在 `Settings.vue` 内实现轻量的本地 Tab UI。

* `Layout.vue` 当前导航模式是左侧一级菜单，`/settings` 仍应保持为单一路由页面，不需要新增路由层级。

## Proposed Changes

### 1. 在 `Settings.vue` 内新增页面级 Tab 导航

目标文件：

* `web/admin/src/views/Settings.vue`

改动内容：

* 在 `script setup` 中新增：

  * `tabs` 配置数组

  * `activeTab` 状态

  * 可选的辅助方法，例如切换 tab、判断当前 tab 是否可保存

* 在页面顶部标题区域下方增加一行 Tab 导航，样式要求：

  * 位于主要内容卡片顶部

  * 横向排列，支持换行或横向滚动

  * 当前 tab 有明确高亮

  * 深浅色主题下视觉一致

* 保持 `/settings` 为单一路由，不新增子路由。

为什么这样做：

* 用户明确要求“顶部以 tab 切换的方式重构页面”。

* 当前没有复用组件，直接在视图文件内实现最符合现有项目结构。

### 2. 按现有字段语义拆成 5 个 Tab

目标文件：

* `web/admin/src/views/Settings.vue`

Tab 分组决策：

1. `站点`

* 基本信息

* 站点运行

* 站点展示

1. `内容`

* 首页展示

* 关于页内容

1. `SEO`

* SEO 设置

* SEO 高级

1. `存储`

* 存储配置

1. `安全`

* 安全设置

改动内容：

* 将当前长页面里的多个 section 抽成按 Tab 条件渲染的内容组。

* 每个 tab 内部仍保留原有 section 标题和输入结构，但减少同屏出现的区块数。

* 避免把完全不同职责的字段继续混在同一 tab 中。

为什么这样做：

* 这 5 组能覆盖当前所有字段，且用户心智最自然：

  * 站点信息与运行参数属于站点层

  * 首页与关于页属于内容展示层

  * SEO 是单独工作流

  * 存储配置复杂且独立

  * 安全设置操作频率低且需要隔离

### 3. 调整保存动作，使其与当前 Tab 语义一致

目标文件：

* `web/admin/src/views/Settings.vue`

改动内容：

* 顶部主按钮继续保留，但文案与启用规则调整为：

  * 在 `站点 / 内容 / SEO / 存储` tab 下显示并继续调用 `saveSettings`

  * 在 `安全` tab 下隐藏该按钮，避免与“保存账号”重复

* `安全` tab 内继续保留单独的“保存账号”按钮，调用现有 `saveAccount`

* 不改动现有 API：

  * `/api/admin/settings`

  * `/api/admin/account`

为什么这样做：

* 当前页面已有两套不同保存逻辑，Tab 化后应让动作边界更清晰。

* 若在安全页仍显示全局“保存设置”按钮，会造成按钮重复和认知负担。

### 4. 优化 Tab 切换体验，但不引入复杂状态管理

目标文件：

* `web/admin/src/views/Settings.vue`

改动内容：

* 使用本地 `ref` 管理 `activeTab`，不引入 store。

* 默认进入 `站点` tab。

* 为了改善刷新和分享体验，使用 URL hash 同步当前 tab，格式建议为：

  * `/settings#site`

  * `/settings#content`

  * `/settings#seo`

  * `/settings#storage`

  * `/settings#security`

* 页面挂载时优先从 `location.hash` 恢复当前 tab；切换 tab 时同步更新 hash。

* 不引入 Vue Router 子路由，不增加后端或路由配置改动。

为什么这样做：

* hash 同步足够轻量，能保留刷新后的当前位置。

* 相比拆成子路由，改动更小，也更符合“一个设置页面内 tab 切换”的需求。

### 5. 保持现有表单逻辑与字段绑定不变，优先做结构重组

目标文件：

* `web/admin/src/views/Settings.vue`

改动内容：

* 保持以下逻辑原样复用：

  * `settings` 的 `reactive` 数据结构

  * `loadSettings`

  * `saveSettings`

  * `loadAccount`

  * `saveAccount`

  * logo 上传逻辑

  * 存储驱动切换逻辑

* 只做以下层面的重排：

  * 顶部标题区

  * tab 导航区

  * 各表单 section 的归位和条件渲染

* 如有必要，可提取少量重复 class 的辅助数组 / 常量，但不拆分成多个新组件。

为什么这样做：

* 本次问题是“页面混乱”，不是“逻辑不可维护”。

* 不拆组件可以把改造范围控制在一个文件内，降低回归风险。

### 6. 兼顾移动端与小屏可用性

目标文件：

* `web/admin/src/views/Settings.vue`

改动内容：

* Tab 导航在移动端使用：

  * 横向滚动容器，或

  * 自动换行的 pill 样式

* 当前 tab 内容区继续沿用现有响应式 grid，避免在小屏出现过窄字段列数。

* 顶部导航与卡片边距延续当前 Tailwind 风格，不单独新增全局 CSS 文件。

为什么这样做：

* 设置页字段很多，小屏下如果 tab 不能滚动或换行，会导致导航不可用。

* 现有后台整体样式已经采用 Tailwind 原子类，实现局部响应式最自然。

## Assumptions & Decisions

* 决定继续使用单页面单路由 `/settings`，不拆成多个设置子页。

* 决定不新增后端接口、不调整设置字段模型，仅重构前端信息架构。

* 决定采用页面内轻量 Tabs，而不是新增通用 Tabs 组件。

* 决定 tab 分组为 `站点 / 内容 / SEO / 存储 / 安全` 五类。

* 决定使用 URL hash 同步当前 tab，但不引入子路由。

* 决定保留安全设置独立保存按钮，并在安全 tab 中隐藏顶部全局保存按钮。

## Verification Steps

* 打开后台 `Settings` 页面后，默认进入 `站点` tab。

* 顶部 tab 可点击切换，视觉高亮明确，深浅色主题显示正常。

* `站点 / 内容 / SEO / 存储 / 安全` 五组内容都能正常显示，且不会同时堆叠成长页面。

* 刷新页面时，若 URL 带 hash，能恢复到对应 tab。

* 在 `站点 / 内容 / SEO / 存储` tab 点击顶部保存按钮，仍能成功调用 `/api/admin/settings`。

* 在 `安全` tab 中点击“保存账号”，仍能成功调用 `/api/admin/account`。

* 切换 `存储` tab 后，本地 / S3 条件表单显示逻辑保持正常。

* 运行前端构建，确认 `Settings.vue` 无模板或脚本错误。
