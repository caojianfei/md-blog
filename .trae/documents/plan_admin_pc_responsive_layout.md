# 管理后台 PC 友好布局改造计划

## Summary

- 目标：把 `web/admin` 当前偏移动端优先的后台布局调整为“PC 端优先、同时兼容移动端”的响应式后台，重点提升右侧内容区的可用宽度，以及文章编辑页在大屏下的写作效率。
- 用户已确认的方向：
  - 后台整体内容区在 PC 端采用“接近全宽”的策略，而不是统一限制在固定 `max-width` 容器内。
  - 文章编辑页在大屏下采用“强化双栏”布局，而不是三段式工作台或纯专注编辑。
  - 编辑器预览模式采用“智能切换”：宽屏默认分屏，中等屏幕默认纯编辑，移动端保持单区切换。
- 范围：仅调整 `web/admin` 前端页面与样式，不改动 Go 后端接口、数据结构与权限链路。

## Current State Analysis

### 全局后台布局现状

- `web/admin/src/components/Layout.vue`
  - 当前主内容容器固定为 `max-w-7xl mx-auto`，这会在大屏下明显压缩右侧内容区宽度。
  - 布局核心仍然是“移动端头部 + 抽屉侧栏 + 单一内容容器”，对桌面端没有提供更强的工作区利用策略。
  - `main` 直接承担滚动容器，适合继续沿用，但需要按路由类型区分内容壳层的宽度与内边距。

### 文章编辑页现状

- `web/admin/src/views/ArticleEdit.vue`
  - 主体仅为 `lg:flex-row` 双栏，右侧设置栏宽度固定在 `lg:w-72 xl:w-80`，在 1440px 及以上屏幕上仍然偏保守。
  - 页面头部、正文工作区、右侧设置栏都处于同一纵向流中，没有形成“桌面端高效工作区”。
  - 标题、Slug、分类、标签、封面、摘要、SEO 全部堆在右侧设置栏中，正文编写与核心元信息之间切换成本高。
  - 预览模式仅在初次挂载时根据 `window.innerWidth < 1024` 做一次判断，没有形成明确的桌面/平板/移动端策略。

### 其他后台页面现状

- `web/admin/src/views/ArticleList.vue`
  - 列表页已经是卡片 + 筛选 + 表格结构，但宽度受全局 `Layout.vue` 限制，桌面端表格横向空间未充分利用。
- `web/admin/src/views/Settings.vue`
  - 自身额外使用了 `max-w-4xl mx-auto`，即使全局放宽后，这一页在桌面端仍会显得偏窄。
- `web/admin/src/views/Dashboard.vue`
  - 卡片区本身可随宽度扩展，主要受全局容器宽度影响。

### 可复用基础

- `web/admin/src/components/MarkdownToolbar.vue` 已具备编辑/分屏/预览三态切换，可在不改动后端的前提下继续扩展桌面端工具栏与布局行为。
- `web/admin/src/components/MarkdownPreview.vue` 已独立封装预览区，适合在桌面端直接作为编辑工作区右半部分使用。
- 项目已存在后台主题切换机制，布局调整需要继续兼容 `light` / `dark` / `system` 三种模式。<mccoremem id="01KRJ3JN96ZCPDV7V8ZMHQNHQS" />

## Assumptions & Decisions

- 全局后台遵循“外层全宽、页面自行决定阅读宽度”的原则：
  - `Layout.vue` 不再对所有页面施加统一 `max-w-7xl`。
  - 页面级组件按内容类型控制自己的最佳宽度。
- 文章编辑页按“桌面工作台”设计，不追求所有信息同时展示，而是优先保证正文编辑区与预览区面积。
- 文章编辑页的信息分层如下：
  - 顶部：页面操作区（返回、状态、保存、发布）。
  - 左侧主工作区：标题、摘要、Markdown 编辑器、预览。
  - 右侧检查器：分类、标签、封面、Slug、SEO 等次级设置，并在桌面端吸顶。
- 预览模式断点决策：
  - `< 1024px`：仅允许 `edit` / `preview`，默认 `edit`，设置栏默认折叠。
  - `1024px - 1279px`：默认 `edit`，允许手动切换 `split`。
  - `>= 1280px`：默认 `split`，充分利用大屏。
- 本次不新增后端接口、不改文章字段、不引入新的状态管理库。

## Proposed Changes

### 1. 调整 `web/admin/src/components/Layout.vue`

- 目标：让后台整体从“统一居中内容页”转为“桌面端近全宽工作台”。
- 具体改造：
  - 移除主内容内层的 `max-w-7xl mx-auto` 限制，改为使用更适合后台的响应式边距，如 `px-4 md:px-6 xl:px-8 2xl:px-10`。
  - 保留现有移动端抽屉侧栏逻辑，但强化桌面端侧栏与内容区的边界感，使内容区成为真正的主工作区域。
  - 基于当前路由增加一个简单的页面类型判断：
    - 文章编辑页使用更紧凑的横向内边距与满高工作区。
    - 普通列表页/仪表盘保留稍大的舒适边距。
  - 确保 `main` 继续作为纵向滚动容器，避免双滚动条问题。
- 原因：全局容器是当前桌面端空间利用不足的最大来源，必须先解除这一层限制，后续单页优化才有意义。

### 2. 调整 `web/admin/src/router/index.js`

- 为文章编辑路由补充页面级 `meta`，例如 `layout: "editor"` 或等价字段。
- `Layout.vue` 通过 `route.meta` 区分普通后台页与编辑工作台页，避免用路径字符串散落判断。
- 原因：桌面编辑页需要与列表页使用不同内容壳层和垂直空间策略，这个差异应该由路由元信息明确表达。

### 3. 重构 `web/admin/src/views/ArticleEdit.vue`

- 目标：把当前“移动端可用的双栏表单页”升级为“桌面端高效写作工作台”。
- 具体改造：
  - 页面根结构改为“顶部操作条 + 主体双栏工作区”。
  - 顶部操作条在桌面端尽量保持单行：
    - 左侧保留返回、页面标题、发布状态。
    - 右侧保留保存草稿与发布按钮。
    - 减少头部纵向占用，把更多高度留给正文工作区。
  - 主体区改为更明确的桌面网格：
    - `xl` 及以上采用类似 `minmax(0,1fr) + 360/380px` 的强化双栏。
    - `lg` 区间保持双栏但缩小检查器宽度。
    - `< lg` 回落为上下堆叠，延续当前移动端兼容性。
  - 将“标题”和“摘要”从右侧设置栏上移到左侧主工作区顶部，作为写作主信息区：
    - 标题使用更高优先级输入框，保证大屏下编辑主标题时不被右侧表单挤压。
    - 摘要保留在正文区上方，便于写作时同步打磨摘要。
  - 右侧设置栏保留次级元信息：
    - 分类、标签、封面、Slug、SEO。
    - 桌面端使用 `sticky` 吸顶，避免长文编辑时频繁滚动寻找设置项。
  - 编辑器工作区高度改为依据视口计算：
    - 保证桌面端正文编辑区和预览区都有稳定可用的可视高度。
    - 避免头部、状态条和外层 padding 过多吞噬高度。
  - 继续保留当前底部状态栏，但精简文案，仅保留字数和模式等高频信息。
- 原因：桌面文章编辑的核心不是“把表单摆出来”，而是最大化正文、标题、预览三者的联动效率。

### 4. 调整 `web/admin/src/components/MarkdownToolbar.vue`

- 目标：让工具栏在大屏编辑场景下更稳定、更容易连续使用。
- 具体改造：
  - 优化工具栏布局，使左侧工具按钮区与右侧预览模式切换区在宽屏下更清晰分组。
  - 在中等屏幕和移动端控制按钮折行/滚动策略，保证不出现遮挡或挤压预览模式开关。
  - 允许 `split` 模式按钮在 `lg` 或基于父组件传入能力条件时显示，而不是当前仅 `sm` 可见的简单控制。
- 原因：编辑页改为工作台后，工具栏会成为高频触达区域，必须与新的断点策略一致。

### 5. 调整 `web/admin/src/components/MarkdownPreview.vue`

- 目标：让预览区在大屏双栏模式下拥有更适合阅读与比对的版式。
- 具体改造：
  - 减少过于保守的内边距，改成对桌面分屏更友好的 padding。
  - 让预览容器在桌面端高度随工作区填满，滚动区域与编辑区保持一致。
  - 保持现有主题同步逻辑不变，只调整布局相关样式。
- 原因：编辑区变宽后，预览区如果仍沿用当前较“内容页”的留白，会浪费可视面积。

### 6. 调整 `web/admin/src/views/ArticleList.vue`

- 目标：让文章列表在桌面端真正受益于全局放宽后的内容区。
- 具体改造：
  - 优化顶部操作区与筛选栏在 `xl` 以上的栅格分布，使搜索、状态、分类、标签筛选更自然地横向展开。
  - 保持移动端筛选折叠逻辑不变。
  - 视情况为表格列增加更合理的最小宽度与对齐方式，让宽屏不再只有大面积留白。
- 原因：用户明确提到“右侧内容区域”需要更 PC 友好，列表页是最直接感知宽度变化的页面之一。

### 7. 调整 `web/admin/src/views/Settings.vue`

- 目标：避免全局放宽后设置页仍因为 `max-w-4xl` 显得过窄。
- 具体改造：
  - 放宽页面最大宽度，例如提升到更大的阅读宽度，或按区块改为桌面双列排布。
  - 保持“关于页内容”编辑区域拥有更大的可视宽度与高度。
  - 不追求完全全宽，但至少与新的后台总体空间策略一致。
- 原因：如果仅 Layout 放宽但设置页保持旧宽度，会造成后台各页面体验割裂。

### 8. 调整 `web/admin/src/styles/base.css`

- 增补后台工作区通用样式，优先放置与布局行为相关、可复用的基础规则，例如：
  - 视口高度相关的工作区最小高度。
  - 桌面工作区卡片的统一圆角、边框和背景层次。
  - 可能需要的滚动条/滚动容器细节优化。
- 保持主题变量与现有暗色模式机制不变。
- 原因：部分布局行为适合沉淀到基础样式层，减少页面组件里重复的工具类堆叠。

## Detailed Implementation Notes

### 文章编辑页的信息优先级

- 一级信息：标题、正文、预览。
- 二级信息：摘要、分类、标签、封面。
- 三级信息：Slug、SEO。
- 因此桌面端优先把一级与二级高频信息留在首屏或一屏可达范围，三级信息放入右侧检查器下半区。

### 智能预览模式行为

- 使用单独的初始化/同步方法替代当前仅在 `onMounted` 中写死的宽度判断。
- 页面首次进入时根据断点设置默认模式。
- 监听窗口尺寸变化时只做“约束修正”：
  - 当屏幕缩小到不适合分屏时，若当前是 `split`，自动回退到 `edit`。
  - 当屏幕重新放大时，不强制覆盖用户刚刚的手动选择，只在首次进入时给默认值。

### 桌面端高度策略

- 编辑页主体区需要接近视口满高，避免出现“页面很宽但真正可编辑区域仍然只有几百像素高”的问题。
- 吸顶设置栏的顶部偏移要与页面操作条和外层 padding 协调，避免遮挡。

## Verification Steps

- 在 `web/admin` 下执行前端构建与诊断检查，确认响应式改造后没有引入新的 Vue 模板或脚本错误。
- 手动验证后台整体布局：
  - 桌面端进入工作台、文章列表、设置页时，内容区明显比当前更宽，且没有不必要的大面积留白。
  - 移动端侧栏抽屉、顶部栏、内容滚动行为保持可用，没有横向滚动条。
- 手动验证文章编辑页：
  - `>= 1280px` 默认分屏，左侧编辑区和右侧预览区同时可用，右侧设置栏吸顶且不遮挡内容。
  - `1024px - 1279px` 默认纯编辑，但可手动切换分屏。
  - `< 1024px` 默认纯编辑，设置栏折叠，仍可切换到预览。
  - 标题与摘要在桌面端进入主工作区后，长文编辑时比当前更顺手。
  - 保存草稿、发布、标签选择、封面上传、SEO 字段等既有能力均不回归。
- 手动验证深浅色主题：
  - `light`、`dark`、`system` 三种模式下，新布局的边框、卡片层次和预览区背景都正常。<mccoremem id="01KRJ3JN96ZCPDV7V8ZMHQNHQS" />
