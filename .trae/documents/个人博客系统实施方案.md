# 个人博客系统实施方案

## Summary

- 目标：从空仓库搭建一个可部署为单个可执行文件的个人博客系统，包含 Go 后端、Vue 管理后台、SSR 文章展示页、Markdown 编辑能力、SQLite/MySQL 双数据库支持，以及浅色/深色主题。
- 已确认决策：
  - 前台采用 Go 服务端渲染（SSR），保证 SEO 友好。
  - 后台采用 Vue SPA，构建后嵌入 Go 二进制统一发布。
  - 后台认证采用单管理员账号。
  - 图片存储同时支持本地存储与 S3 兼容对象存储。
  - 文章流程首版支持草稿 / 已发布。
  - 前台首版包含：首页、分类页、标签页、搜索页、归档页、关于页、文章详情页。
  - 搜索范围覆盖标题、摘要、正文。
  - SEO 首版包含：语义化页面、meta、Open Graph、RSS、sitemap、robots。

## Current State Analysis

- 当前仓库为空目录，未发现任何已有代码、配置文件、脚手架、数据库迁移或前端工程。
- 当前不存在 `.trae` 目录，也不存在可复用的项目结构，因此需要从零设计项目布局、构建流程和部署方式。
- 因为目标要求最终发布为单个可执行文件，所以需要优先采用“Go 为主进程 + 嵌入前端静态资源 + 自带 SSR 模板”的一体化架构，而不是运行期依赖独立 Node 服务。

## Assumptions & Decisions

- 首版范围不包含评论、友链、多作者协作、公开 API、全文推荐、消息通知、工作流审批。
- 每篇文章仅属于一个分类，可绑定多个标签。
- 关于页作为站点配置中的单页内容存储，而不是单独的 CMS 模块。
- 搜索首版采用数据库查询实现：
  - SQLite 使用 `LIKE` / `instr` 配合索引。
  - MySQL 使用 `FULLTEXT`（可用时）或回退到 `LIKE`。
- Redis 不是首版必需组件，保留为可选能力，仅用于未来缓存、限流或会话扩展。
- 单可执行文件的定义：
  - Go 服务二进制内嵌管理后台静态资源和前台模板资源。
  - 运行时仅额外依赖数据库与外部对象存储（若启用）。
  - 本地上传图片与 SQLite 数据文件落盘到可配置数据目录。

## Proposed Changes

### 1. 项目整体目录与构建组织

- 新增 `go.mod`
  - 初始化 Go 主工程。
  - 引入 HTTP 路由、配置、ORM/SQL、模板、Markdown 渲染、对象存储等依赖。
- 新增 `cmd/server/main.go`
  - 作为唯一启动入口。
  - 负责加载配置、初始化数据库、挂载路由、启动 HTTP 服务。
- 新增 `internal/config/`
  - 定义配置结构、环境变量解析、默认值和启动校验。
  - 覆盖数据库、站点信息、上传存储、管理员初始化、主题和 SEO 基础配置。
- 新增 `internal/bootstrap/`
  - 负责依赖装配：数据库连接、迁移执行、模板引擎、存储驱动、服务注册。
- 新增 `internal/router/`
  - 拆分公共前台路由、后台 API 路由、静态资源路由、健康检查路由。
- 新增 `web/admin/`
  - Vue 管理后台工程。
  - 使用构建产物输出到可嵌入目录，再由 Go 使用 `embed` 打包。
- 新增 `web/templates/`
  - 前台 SSR 模板，包括首页、文章页、分类页、标签页、搜索页、归档页、关于页、错误页。
- 新增 `web/assets/`
  - 前台共享样式、主题变量、少量增强脚本、默认图标和社交分享资源。
- 新增 `build/`
  - 放置构建脚本与打包辅助脚本，用于先构建前端、再执行 Go 编译。

### 2. 后端领域模型与数据库设计

- 新增 `internal/model/`
  - `article.go`：文章主体，字段包含标题、slug、摘要、Markdown 正文、HTML 缓存、状态、分类、SEO 字段、封面图、发布时间。
  - `category.go`：分类信息，包含名称、slug、描述、排序。
  - `tag.go`：标签信息，包含名称、slug、描述。
  - `article_tag.go`：文章与标签关联表。
  - `site_setting.go`：站点名称、简介、关于页内容、主题默认值、SEO 默认配置、社交链接等。
  - `admin_user.go`：单管理员账号信息、密码哈希、最后登录时间。
  - `media.go`：图片和附件元数据，记录存储类型、对象 key、访问 URL、尺寸、MIME。
- 新增 `internal/repository/`
  - 提供文章、分类、标签、媒体、站点设置、管理员的数据库访问层。
  - 屏蔽 SQLite 与 MySQL 语法差异。
- 新增 `internal/migration/`
  - 提供建表、索引、初始化默认数据、数据库兼容迁移。
  - 明确为 SQLite 和 MySQL 生成兼容 DDL。

### 3. 业务服务层

- 新增 `internal/service/article/`
  - 负责文章创建、更新、发布、取消发布、搜索、按标签/分类筛选、归档聚合。
  - 保存时同时生成 slug、摘要兜底、HTML 缓存、阅读元信息。
- 新增 `internal/service/markdown/`
  - 统一处理 Markdown 转 HTML。
  - 支持代码高亮、表格、任务列表、脚注、标题锚点、外链安全属性。
  - 生成目录所需标题结构，供前台文章页使用。
- 新增 `internal/service/media/`
  - 处理图片上传、文件类型校验、尺寸/大小限制、缩略信息提取、访问 URL 生成。
  - 对接本地存储与 S3 兼容对象存储。
- 新增 `internal/service/search/`
  - 统一封装搜索条件构造，支持标题、摘要、正文。
  - 根据不同数据库能力选择查询策略。
- 新增 `internal/service/auth/`
  - 处理后台登录、会话校验、密码哈希、单管理员初始化。
- 新增 `internal/service/seo/`
  - 生成 canonical、meta、Open Graph、RSS、sitemap、robots 所需数据。

### 4. 后台 API 设计

- 新增 `internal/handler/api/`
  - `auth_handler.go`：登录、退出、当前用户信息。
  - `dashboard_handler.go`：工作台统计，输出文章总数、已发布数、草稿数、分类数、标签数、最近文章。
  - `article_handler.go`：文章 CRUD、发布状态切换、预览、搜索、slug 校验。
  - `category_handler.go`：分类 CRUD。
  - `tag_handler.go`：标签 CRUD。
  - `media_handler.go`：图片上传、媒体列表、删除。
  - `setting_handler.go`：站点配置、关于页内容、SEO 默认配置维护。
- API 约定：
  - 后台统一走 `/api/admin/*`。
  - 返回结构统一为 `code/message/data`。
  - 鉴权采用基于 Cookie 的服务端会话，避免首版引入额外 token 管理复杂度。
  - 文章预览接口直接接收 Markdown 内容并返回渲染后的 HTML 片段，用于编辑器实时预览。

### 5. 管理后台实现

- 新增 `web/admin/src/`
  - 页面包含：工作台、文章管理、标签管理、分类管理、站点设置、登录页。
- 新增 `web/admin/src/router/`
  - 管理后台路由守卫与登录态校验。
- 新增 `web/admin/src/api/`
  - 封装后台接口请求。
- 新增 `web/admin/src/views/dashboard/`
  - 工作台展示基础统计与最近文章。
- 新增 `web/admin/src/views/article/`
  - 文章列表页：搜索、状态筛选、分类筛选、标签筛选、分页。
  - 编辑页：标题、slug、摘要、分类、标签、封面、SEO 字段、Markdown 编辑器。
- 新增 `web/admin/src/views/category/` 与 `web/admin/src/views/tag/`
  - 管理分类和标签的增删改查。
- 新增 `web/admin/src/views/settings/`
  - 管理关于页、站点信息、主题配置、SEO 默认项、对象存储配置。
- 编辑器方案决策：
  - 采用成熟 Markdown 编辑器组件，要求具备分屏预览、快捷工具栏、粘贴/上传图片、插入链接、标题与代码块快捷输入能力。
  - 预览优先提供实时侧边预览与单独预览模式。
  - 图片插入流程：本地选择或拖拽上传 -> 调用媒体接口 -> 自动插入 Markdown 图片语法。
  - 链接插入流程：通过工具栏弹窗填写文本与 URL，自动插入链接语法。
  - 体验优化：自动保存草稿、离开页提醒、快捷键、字数统计、滚动同步、错误提示。
- UI 风格：
  - 采用现代简洁风格设计系统。
  - 后台支持浅色 / 深色主题切换，并与前台共享基础色板变量。

### 6. 前台 SSR 页面实现

- 新增 `internal/handler/web/`
  - `home_handler.go`：首页文章列表与分页。
  - `article_handler.go`：文章详情页。
  - `category_handler.go`：分类页。
  - `tag_handler.go`：标签页。
  - `search_handler.go`：搜索结果页。
  - `archive_handler.go`：归档页。
  - `about_handler.go`：关于页。
  - `feed_handler.go`：RSS、sitemap、robots 输出。
- 新增 `web/templates/layouts/`
  - 布局模板、页头、页脚、SEO 头部片段、分页组件、主题切换组件。
- 新增 `web/templates/pages/`
  - 各页面模板文件。
- 新增 `web/templates/partials/`
  - 文章卡片、标签列表、分类导航、搜索框、空状态组件。
- 页面能力：
  - 首页展示最新已发布文章，支持分页。
  - 分类页和标签页展示对应文章列表。
  - 搜索页展示关键词检索结果，并对关键词进行安全处理。
  - 归档页按年月聚合文章。
  - 文章详情页支持目录、代码高亮、封面图、上一篇/下一篇（可选但建议）。
  - 关于页读取站点设置中的 Markdown 内容并渲染展示。

### 7. SEO 与可发现性

- 在 `internal/service/seo/` 与 `web/templates/partials/seo_head.html` 中统一输出：
  - 每页 title、description、keywords、canonical。
  - Open Graph 与 Twitter Card 基础字段。
  - robots 控制。
- 新增 `internal/handler/web/feed_handler.go`
  - 输出 `/sitemap.xml`、`/rss.xml`、`/robots.txt`。
- SEO 决策：
  - 所有公开页面使用 SSR 输出核心内容，避免仅客户端渲染。
  - URL 采用语义化路径，如 `/posts/{slug}`、`/categories/{slug}`、`/tags/{slug}`。
  - 自动生成文章 slug，允许后台手动覆盖。
  - 保证分页、分类、标签、搜索结果页具备独立 meta 信息。

### 8. 认证、安全与运行时配置

- 新增 `internal/middleware/`
  - 后台鉴权、CSRF（若采用表单/会话混合）、安全头、日志恢复。
- 新增 `internal/security/`
  - 密码哈希、上传文件校验、HTML 安全过滤策略。
- 配置项覆盖：
  - 服务监听地址、站点基础 URL。
  - 数据库驱动（sqlite/mysql）和连接参数。
  - 本地上传目录或对象存储连接信息。
  - 管理员初始化账号。
  - 日志级别与运行环境。

### 9. 单可执行文件打包策略

- 在 `cmd/server/main.go` 或独立 `internal/embed/` 中使用 `embed`：
  - 嵌入后台构建产物。
  - 嵌入前台模板和静态资源。
- 新增 `build/build.sh`
  - 先构建 Vue 后台。
  - 再执行 Go 编译，生成单个服务二进制。
- 构建产物设计：
  - 二进制启动后同时提供后台 API、后台静态资源、前台 SSR 页面。
  - 若使用 SQLite，本地数据目录可单独挂载；若使用 MySQL，则二进制不依赖本地数据库文件。

### 10. 测试与质量保障

- 新增 `internal/service/.../*_test.go`
  - 覆盖 slug 生成、Markdown 渲染、搜索条件、文章发布逻辑、媒体存储策略。
- 新增 `internal/handler/.../*_test.go`
  - 覆盖关键路由、状态码、SEO 输出、RSS/sitemap 输出。
- 新增 `web/admin` 侧关键交互测试
  - 重点覆盖文章编辑页：图片上传插入、链接插入、实时预览、保存草稿。
- 手工验收重点：
  - SQLite 与 MySQL 两套配置均可启动。
  - 后台登录、文章新增、草稿保存、发布、分类/标签筛选、搜索、归档展示正常。
  - 前台页面在无 JS 场景下仍可看到核心文章内容。
  - 打包结果为单个可执行文件，启动后即可访问前台与后台。

## Implementation Order

1. 初始化 Go 主工程、配置加载、数据库连接与迁移框架。
2. 建立核心模型、仓储层、文章/分类/标签/设置服务。
3. 完成后台认证、工作台、文章管理、分类管理、标签管理 API。
4. 落地 Markdown 渲染服务与媒体上传存储抽象。
5. 搭建 Vue 管理后台，优先完成文章编辑体验。
6. 实现前台 SSR 页面、分页、标签/分类筛选、搜索、归档、关于页。
7. 补齐 SEO 输出、RSS、sitemap、robots。
8. 打通前端构建嵌入与单二进制打包。
9. 完成自动化测试与联调验收。

## Verification Steps

- 使用 SQLite 配置启动服务，验证初始化流程、后台登录、文章管理、前台展示。
- 切换 MySQL 配置后再次启动，验证迁移、CRUD、搜索和筛选正常。
- 上传图片到本地存储，验证 Markdown 中自动插入图片语法与前台访问。
- 切换对象存储配置后再次上传图片，验证媒体 URL 生成与访问链路。
- 在后台编辑器中验证：
  - Markdown 实时预览。
  - 图片插入。
  - 链接插入。
  - 自动保存草稿。
  - 深色 / 浅色主题表现。
- 在前台验证：
  - 首页分页。
  - 分类页、标签页、搜索页、归档页、关于页。
  - 文章详情页 SEO meta、Open Graph、RSS、sitemap、robots。
- 执行完整构建流程，确认最终产物为单个可执行文件且可独立运行。
